# FuturesArbBot

**Межбиржевой арбитражный робот для фьючерсов** на свежем .NET 10 (C#) с использованием официального порта [CCXT](https://github.com/ccxt/ccxt) (NuGet-пакет `ccxt`) и консольного интерфейса [Spectre.Console](https://spectreconsole.net/).

Робот непрерывно опрашивает несколько криптобирж, сравнивает цены **линейных бессрочных фьючерсов (USDT-перпов)** по всем доступным торговым парам и находит расхождения, при которых одновременная покупка «там дешевле» и продажа «там дороже» приносит прибыль с учётом комиссий обеих бирж.

> ⚠️ **Дисклеймер.** Торговля фьючерсами с плечом — деятельность высокого риска. Данный проект — исследовательский инструмент, а не финансовый совет. Авторы не несут ответственности за финансовые потери. Всегда начинайте с режимов `DryRun` и `Testnet`.

---

## Возможности

- **Мониторинг всех доступных пар**: по умолчанию робот берёт все линейные бессрочные контракты в USDT (~1500–2000 инструментов на трёх биржах) с фильтром по обороту за 24 часа.
- **Арбитраж по «коридору спреда»**: два настраиваемых порога — вход при расхождении **вверх** (`MinSpreadPercentUp`) и фиксация прибыли при сжатии **вниз** (`MinSpreadPercentDown`), плюс стоп-лосс.
- **Учёт комиссий бирж**: нетто-спред = валовый спред − taker-комиссия обеих ног − буфер на проскальзывание. Комиссии автоматически подтягиваются из рынков CCXT (можно переопределить в конфиге).
- **Выбор режима сети**: `DryRun` (симуляция без ордеров) → `Testnet` (тестовая сеть биржи) → `Live` (реальная торговля, требует явного подтверждения).
- **Биржи через конфиг**: добавление/отключение биржи — одна строка в `exchanges.json`, без изменения кода.
- **Пары через конфиг**: белые и чёрные списки с wildcard-шаблонами (`BTC/USDT:*`, `*UP/USDT:*`).
- **Живой дашборд** в терминале: таблица лучших возможностей, журнал событий, строка статистики (Spectre.Console Live).
- **Ctrl+C — корректная остановка** с подробной статистикой сеанса: тики, тикеры, сигналы, сделки, PnL, топ символов, статистика по биржам, последние ошибки.
- **Защита от аномалий**: санитарный потолок спреда отсекает «фантомные» расхождения новых листингов и препаратов.
- **Настраиваемое исполнение заявок**: market / limit / chase-limit (догонание цены шагами), смещение цены в bps, time-in-force (включая post-only) и отдельные правила для закрытия — с автоматическим понижением до того, что биржа действительно поддерживает.
- **Модульная архитектура**: ядро не зависит от биржевой библиотеки, CCXT спрятан за адаптером `IExchangeConnector`; 73 модульных теста; CI на GitHub Actions.

## Как это работает

Каждые `RefreshIntervalMs` миллисекунд робот:

1. **Опрашивает биржи** (параллельно, с изоляцией ошибок): для Binance дополнительно досиливаются bid/ask из bookTicker, объём OKX извлекается из сырых данных.
2. **Фильтрует пары**: только линейные бессрочные фьючерсы, заданные котиры (USDT), минимальный оборот за 24 ч, белый/чёрный список, лимит `MaxSymbols` (берутся самые ликвидные).
3. **Ищет расхождения**: по каждому символу, присутствующему минимум на двух биржах, берётся пара «самая дешёвая цена покупки (ask) — самая дорогая цена продажи (bid)».
4. **Считает нетто-спред**:

```
валовый спред, %    = (bid_дорогой − ask_дешёвой) / ask_дешёвой × 100
нетто, %            = валовый − taker_дешёвой% − taker_дорогой% − проскальзывание%
```

5. **Работает как коридор** (при включённой торговле `Arbitrage.Enabled = true`):

```
 нетто-спред, %
      ▲
  U ──┼──────── открываем арбитраж, когда спред пробил порог «вверх» (U)
      │        ╱╲        ╱╲
  D ──┼──────╱────╲──╱────── закрываем с прибылью при сжатии до порога «вниз» (D)
      │  ╱╱        ╲╲
  S ──┼───────────────────── стоп-лосс: если спред вырос до S — закрываем в убыток
      └──────────────────────► время
```

Позиция — дельта-нейтральная связка фьючерсов: **лонг на дешёвой бирже + шорт на дорогой**. Прибыль фиксируется при сжатии спреда, независимо от направления движения базового актива.

### Как исполняются сделки

- **Открытие** — двумя **marketable limit-ордерами**: покупка по ask дешёвой биржи, продажа по bid дорогой (лучше указанной цены не будет, но и проскальзывание за её пределы исключено). Тип заявки, смещение цены и догонание настраиваются разделом [`Arbitrage.Execution`](#тип-заявки-смещение-цены-и-догонание-arbitrageexecution). Ноги выставляются последовательно: **отказ первой ноги — вторая не выставляется вообще**.
- После приёма заявок робот ждёт **полного исполнения обеих ног** (`OrderExecutionTimeoutMs`, опрос раз в `OrderPollIntervalMs`). Если нога не доисполнилась, а политике положено догонание (`Type = ChaseLimit`), заявка снимается и переставляется ближе к рынку — до `MaxSteps` раз в пределах `MaxDeviationBps`, после чего остаток добивается market-ордером (`FallbackToMarket`) либо ноги откатываются.
- Если нога отклонена, отменена или не доисполнилась за таймаут — живые заявки **отменяются**, а фактически набранный объём **откатывается** market `reduceOnly`-ордерами с ретраями. Позиция не регистрируется.
- Если откат пройти не мог (биржа «не отдаёт» объём), остаток **не теряется**: позиция регистрируется с фактическими раздельными объёмами ног (`LongSize`/`ShortSize`) и передаётся циклу ведения.
- **Ребалансировка**: перекос ног сверх `RebalanceTolerancePercent` (но не меньше минимального лота биржи) устраняется обрезкой **бóльшей** ноги `reduceOnly`-заявкой — экспозиция и маржа не растут; тип и цена — по политике входа, остаток добирается на следующем тике.
- **Закрытие** (тейк/стоп/таймаут/выход) — по умолчанию market `reduceOnly` по фактическому объёму каждой ноги (`Execution:Close:Type = Limit` — с ожиданием исполнения); если нога не закрылась, позиция остаётся в учёте и закрытие повторяется на каждом следующем тике.

## Архитектура

```
FuturesArbBot/
├── config/                         ← вся настройка здесь (JSON, hot-reload)
├── src/
│   ├── FuturesArbBot.Core/         ← ядро: не знает ни о CCXT, ни о консоли
│   │   ├── Domain/                 ← модели: тикеры, спреды, позиции, опции,
│   │   │                              политика заявок (Execution) и отчёты
│   │   ├── Abstractions/           ← интерфейсы: IExchangeConnector, ITradeExecutor…
│   │   └── Engine/                 ← сканер, калькулятор спредов, фильтр пар,
│   │                                  исполнитель сделок, статистика, журнал
│   ├── FuturesArbBot.Infrastructure/
│   │   ├── Ccxt/                   ← адаптер CCXT + фабрика бирж
│   │   └── Configuration/          ← загрузка и горячая перечитка JSON-конфигов
│   └── FuturesArbBot.App/          ← консоль: DI, баннер, Live-дашборд, отчёты
└── tests/FuturesArbBot.Tests/      ← модульные тесты ядра (xUnit)
```

Ключевые принципы:

- **Ядро чистое**: `FuturesArbBot.Core` не имеет зависимости от CCXT — биржа подменяется реализацией `IExchangeConnector` (в тестах — фейковая биржа). CCXT можно заменить на прямые REST API, не трогая логику.
- **Ошибка одной биржи не роняет сеанс**: опрос каждой биржи изолирован, сбои логируются и учитываются в статистике.
- **Горячая конфигурация**: правки `appsettings.json`/`symbols.json` подхватываются без перезапуска (список бирж — при перезапуске).
- **Современный C#** (.NET 10, C# 14): primary constructors, collection expressions, extension-члены, ключевое слово `field`, `System.Threading.Lock`, `TimeProvider`, `params ReadOnlySpan<T>`, null-conditional assignment, records, required-свойства.

## Установка и быстрый старт

```bash
git clone <репозиторий> FuturesArbBot
cd FuturesArbBot

dotnet restore

# 1) Симуляция одного сканирования: подключится к биржам и покажет возможности
dotnet run --project src/FuturesArbBot.App -- --once

# 2) Постоянный мониторинг в DryRun (ордера НЕ отправляются)
dotnet run --project src/FuturesArbBot.App

# 3) Без Live-дашборда (простой текстовый поток событий)
dotnet run --project src/FuturesArbBot.App -- --no-ui

# Запуск из другого каталога:
dotnet run --project src/FuturesArbBot.App -- --config-dir /путь/к/config
```

Ключи API для мониторинга **не нужны** — тикеры это публичные данные. Ключи понадобятся, только когда включите торговлю.

```bash
docker build -t futures-arb-bot .

```

### Тип заявки, смещение цены и догонание (`Arbitrage.Execution`)

Раздел **необязательный**: если его нет, робот ведёт себя как раньше — вход **marketable limit**
(по ask дешёвой биржи / по bid дорогой), закрытие **market**.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `Execution:Type` | `Limit` (вход), `Market` (закрытие) | `Market` \| `Limit` \| `ChaseLimit` (лимитная заявка с догонанием цены) |
| `Execution:LimitOffsetBps` | `0` | Смещение цены от котировки в bps (1 bps = 0.01 %). `BUY` — выше (агрессивнее), `SELL` — ниже. Отрицательное значение = «пассивнее» |
| `Execution:TimeInForce` | `GTC` | `GTC` \| `Ioc` \| `Fok` \| `PostOnly` (post-only — заявка не должна разбрать стакан) |
| `Execution:Chase:Mode` | `Simulated` | `Simulated` — перестановки делает робот; `Native` — chase-ордер биржи; `None` — обычная limit |
| `Execution:Chase:MaxSteps` | `5` | Сколько раз переставить заявку, прежде чем сдаться |
| `Execution:Chase:StepIntervalMs` | `400` | Пауза между перестановками, мс |
| `Execution:Chase:StepBps` | `5` | Шаг смещения цены к рынку, bps |
| `Execution:Chase:MaxDeviationBps` | `50` | Бюджет отклонения от стартовой цены; сверх него заявка не догоняется |
| `Execution:Chase:FallbackToMarket` | `true` | `true` — добить остаток market; `false` — отменить и откатать набранное (как без chase) |
| `Execution:Chase:Params` | — | Нативные параметры биржи для `Mode: Native` (см. ниже) |
| `Execution:Close:*` | `Type = Market` | Отдельная политика закрытия. `Chase` на закрытии не допускается — будет market |

Пример: вход chase-заявкой с шагом 5 bps, но не дальше 50 bps от котировки; закрытие — limit:

```jsonc
"Arbitrage": {
  "OrderExecutionTimeoutMs": 6000,   // весь цикл догонания укладывается в этот таймаут
  "Execution": {
    "Type": "ChaseLimit",
    "LimitOffsetBps": 2,
    "Chase": { "Mode": "Simulated", "MaxSteps": 6, "StepIntervalMs": 350, "StepBps": 5, "MaxDeviationBps": 60, "FallbackToMarket": true },
    "Close": { "Type": "Limit", "LimitOffsetBps": 5 }
  }
}
```

Переопределение на отдельную биржу (exchanges.json) — достаточно полей, которые отличаются:

```jsonc
{
  "Id": "bybit",
  "Enabled": true,
  "Execution": { "LimitOffsetBps": 15, "Chase": { "MaxSteps": 2 } }
}
```

**Как работает догонание (`Simulated`).** Робот выставляет limit-заявку, ждёт `StepIntervalMs`,
и если объём не набран — снимает заявку, фиксирует частичное исполнение и выставляет остаток
на шаг (`StepBps`) ближе к рынку. Так до `MaxSteps` раз, пока не упрётся в `MaxDeviationBps`.
Дальше — market-добивка остатка (`FallbackToMarket: true`) или отказ со стандартным откатом.
Средняя цена входа считается как средневзвешенная по всем заявкам ноги.
С `TimeInForce = PostOnly` каждая перестановка тоже только мейкерская: если биржа отклонит
такую заявку (она разминулась со стаканом), нога считается мёртвой и включается обычный откат.
`ChaseLimit` вместе с `Ioc`/`Fok` не имеет смысла (остаток снимается сразу) — политика
понижает его до обычного `Limit` и сообщает об этом.

**Возможности бирж и безопасное понижение.** Перед стартом (`OrderConfigValidator`) и при
развёртывании политики (`OrderPolicyResolver`) неподдерживаемое не отправляется на биржу, а
понижается с предупреждением в журнал и в консоль:

| Биржа | Limit / cancel / fetch | Post-only (`timeInForce`) | IOC | FOK | Нативный chase |
|---|---|---|---|---|---|
| `binanceusdm`, `binance` | + | — | + | + | — |
| `bybit` | + | `PostOnly` | + | + | — |
| `okx` | + | `PO` | + | + | — |
| `gate` | + | `post_only` | + | — | — |
| `mexc` | + | — | — | — | — |
| `kucoinfutures` | + | — | + | — | **+** |
| `bitget` | + | `post_only` | + | + | — |
| `htx` | + | — | + | + | — |
| `coinex`, `phemex`, `krakenfutures`, неизвестные | + | — | — | — | — |

Примеры понижения: `ChaseLimit` + `Mode: Native` на Binance → `Simulated`; `PostOnly` там же → `GTC`;
`ChaseLimit` на бирже без отмены заявок → обычный `Limit`; `ChaseLimit` вместе с `Ioc`/`Fok` →
обычный `Limit` (биржа сама снимает остаток, переставлять нечего). Таблица — это `ExchangeCapabilityMap`
(`src/FuturesArbBot.Core/Domain/OrderExecution.cs`), её надо сверять при обновлении CCXT.

При старте робот печатает сводку по каждой бирже — какая заявка там реально будет использоваться
(после понижений) и что именно понижено:

```
· Binance USD-M Futures: вход — ChaseLimit (локальные перестановки: до 5 шагов по 5 bps, не дальше 50 bps от старта, остаток — market), закрытие — Market
! Binance USD-M Futures: нативный chase на binanceusdm недоступен — используется локальное догонание (Simulated)
· KuCoin Futures: вход — ChaseLimit (нативный chase биржи, параметры: chaseType), закрытие — Market
```

**Нативный chase (`Mode: Native`) — опция «для тех, кто проверил».** Робот выставляет такую заявку
через единый `createOrder` CCXT, добавляя в `params` содержимое `Execution:Chase:Params` как есть.
Гарантии, что биржа поймёт её именно как chase, тут нет: у KuCoin Futures «догоняющий» ордер в CCXT
вынесен в отдельный неявный метод `contractPrivatePostOrderChaseLimitOrder`, и единый `createOrder`
туда не ходит. Поэтому `Native` обязан быть проверен на testnet по документации своей биржи
(имена параметров + факт догонания цены), а до проверки разумно использовать `Simulated`.
Если `Params` пустой, политика сама понизит режим до `Simulated` и сообщит об этом.
При `Native` робот не делает локальных перестановок: выставляется одна заявка, а её исполнением
биржа занимается сама — робот ждёт до `OrderExecutionTimeoutMs`, затем отменяет и откатывает набранное.

```jsonc
// только после проверки на testnet: Mode = Native требует непустого Params
"Execution": {
  "Type": "ChaseLimit",
  "Chase": { "Mode": "Native", "FallbackToMarket": false, "Params": { "chaseType": "priceChase" } }
}
```

### Сверка лимитов с биржей

Лимиты `MaxOpenPositions` и `MaxPositionsPerExchange` считаются не только по позициям текущего сеанса, но и по **фактической экспозиции на биржах**. Перед каждым сканом возможностей (не чаще раза в минуту — `fetchPositions` это приватный запрос) робот опрашивает позиции каждой подключённой биржи:

- **Позиции вне учёта сеанса занимают слоты лимитов.** Символ с ненулевой экспозицией сразу на двух и более биржах засчитывается как внешний арбитраж (`MaxOpenPositions`), каждая отдельная «одиночная» нога занимает слот своей биржи (`MaxPositionsPerExchange`). После рестарта бот не откроет «ещё одну» сделку поверх оставшейся на биржах связки.
- **Свои позиции не считаются дважды** — символы позиций, которые робот ведёт в этом сеансе, исключаются из снимка сверки.
- **Чужая одноногая экспозиция** (например, лонг по `X/USDT` только на одной бирже) занимает один слот `MaxPositionsPerExchange` этой биржи, но не слоты других бирж и не слот арбитража.
- **При сбое сверки** сохраняется последний известный снимок экспозиции — слоты лимитов не «освобождаются» из-за сетевой недоступности биржи; о сбое пишется предупреждение в журнал (одно на биржу).
- **В `DryRun`** сверка пропускается: заявок в симуляции нет, сверяться не с чем.
- Если `fetchPositions` не поддерживается биржей (ошибка в журнале), лимиты по этой бирже считаются только по позициям сеанса.

От «потерь» учёта цикл ведения дополнительно защищает ещё две ситуации:

- **Неотменённые при откате открытия заявки не забываются**: каждый тик робот пробует отменить их снова, пока они живы в стакане; если такая заявка самоисполнилась — символ занимает слот внешней экспозиции до закрытия.
- **Закрытие market-ордером засчитывается только подтверждённым**: по исполненному объёму в статусе заявки (`fetchOrder`) либо по отсутствию позиции в `fetchPositions`. Без подтверждения нога считается открытой, позиция остаётся в учёте, и закрытие повторяется на следующем тике.

### `symbols.json` — торговые пары

По умолчанию: **все** линейные бессрочные фьючерсы в USDT с оборотом от 5 млн USDT/сутки, максимум 400 самых ликвидных.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `QuoteCurrencies` | `["USDT"]` | Котиры (например, `["USDT", "USDC"]`) |
| `MinQuoteVolume24hUsd` | `5000000` | Минимальный оборот за 24 ч, USDT |
| `MaxSymbols` | `400` | Предел числа отслеживаемых пар (берутся самые ликвидные) |
| `MaxTickerAgeSeconds` | `15` | Устаревшие тикеры не участвуют в расчёте |
| `Include` | `[]` | **Белый список** шаблонов (если не пуст — только эти пары) |
| `Exclude` | `[]` | **Чёрный список** шаблонов |

Шаблоны поддерживают `*` (любая последовательность) и `?` (один символ), без учёта регистра:

```jsonc
"Include": [ "BTC/USDT:*", "ETH/USDT:*" ]      // только BTC и ETH
"Exclude": [ "*UP/USDT:*", "1000*/USDT:*" ]    // без леверидж-токенов и 1000X-вариантов
```

> Unified-символ CCXT выглядит как `BTC/USDT:USDT` (базис/котиры:сеттлмент). Совпадение пар между биржами идёт по этому имени, поэтому `1000PEPE/USDT:USDT` на одной бирже не «склеится» с `PEPE/USDT:USDT` на другой — используйте `Exclude`/`Include`, если это мешает.

## Режимы сети

| Режим | Что происходит | Ключи |
|---|---|---|
| **DryRun** | Полный цикл сканирования; «сделки» симулируются по текущим bid/ask, PnL считается виртуально. Идеально для проверки настроек | не нужны |
| **Testnet** | Реальные ордера на тестовой сети биржи (`setSandboxMode`), условные деньги | тестнет-ключи биржи |
| **Live** | Реальные ордера на реальные деньги | боевые ключи + `Arbitrage:AllowLive = true` |

Чек-лист включения реальной торговли:

1. `General:NetworkMode = "Testnet"` (сначала!), `Arbitrage:Enabled = true`, ключи в `exchanges.json` или `ARB_*`-переменных.
2. Запуск — робот сам проверит ключи приватным запросом (`VerifyAccessAsync`).
3. Отработайте хотя бы день на Testnet, только потом `NetworkMode = "Live"` + `Arbitrage:AllowLive = true`.
4. Начните с малого `OrderSizeUsd` и большого `MinSpreadPercentUp`.

Защита от опечаток: в режиме Live без `AllowLive` робот **откажется запускаться**; при невалидных ключах торговля не включится.

## Управление

- **Ctrl+C** — корректная остановка: сканер завершает текущий тик, позиции закрываются (если `ClosePositionsOnExit`), после чего печатается **подробный отчёт сеанса**:
  - режим, длительность, тики, тикеры, сигналы (и в час), лучший спред за сеанс;
  - таблица закрытых арбитражей с PnL по каждому и итоговая PnL (с учётом комиссий);
  - позиции, оставшиеся открытыми;
  - статистика по биржам: рынков, запросов, ошибок, средняя задержка, taker-комиссия;
  - гистограмма «топ символов по числу сигналов»;
  - последние ошибки.
  Повторный Ctrl+C — принудительное завершение.
- **Журнал** дублируется в `logs/session-YYYYMMDD-HHmmss.log` (все уровни, включая Debug).

## FAQ

**Почему сигнал есть, а робот не торгует?** — По умолчанию `Arbitrage:Enabled = false`: это монитор. Включите торговлю и пройдите чек-лист режима сети.

**Вижу спред 3 %, а робот молчит.** — Проверьте `MaxSpreadPercent` (аномалии отбрасываются), нетто-спред с учётом комиссий (может уйти в минус), объём и `MinQuoteVolume24hUsd`.

**Лимиты свободны, а новые арбитражи не открываются.** — Робот считает не только позиции текущего сеанса, но и фактическую экспозицию на биржах (см. [Сверка лимитов с биржей](#сверка-лимитов-с-биржей)). Остатки после рестарта или ручные сделки под теми же ключами занимают слоты — ищите в журнале предупреждение «На биржах найдены позиции вне учёта этого сеанса».

**Реально ли заработать на межбиржевом арбитраже?** — Чистые расхождения на топ-биржах редки и малы (обычно < 0.2 %). Плюс: задержки сети, проскальзывание, лимиты бирж, перевод денег между биржами. Робот показывает реальную картину с учётом комиссий — решать вам.

**Что такое «стоковые перпы» (AAPL, TSLA на Binance)?** — В 2025–2026 биржи начали листить бессрочные контракты на акции. Их цены на разных биржах считаются от разных индексов, поэтому «спреды» между ними фиктивны — санитарный потолок `MaxSpreadPercent` их отсекает.

**Можно ли добавить спот?** — Да: реализуйте `IExchangeConnector` (или разрешите спот-рынки в коннекторе) — ядро менять не нужно. Но проект сфокусирован на фьючерсах.

**Много запросов к бирже?** — При 3 биржах и интервале 2 с это ~3 запроса/с с `enableRateLimit` в CCXT. Не ставьте интервал меньше 1 с на все биржи сразу.

## Ограничения и риски

- Открытие исполняется **limit-ордерами** — риск не исполниться покрывается таймаутом с отменой и откатом; закрытие/откаты — **рыночные ордера**, на неликвидных парах возможно проскальзывание (буфер `SlippageBufferPercent` и фильтр объёма снижают, но не устраняют риск).
- **Догонание цены (`ChaseLimit`) — компромисс скорости и цены.** Каждый шаг — это отмена + новая заявка, поэтому растёт число запросов к бирже (нужен запас по rate limit) и среднее время открытия; при `FallbackToMarket = true` остаток добирается по market-цене, то есть «гарантия исполнения» оплачивается проскальзыванием. Весь цикл догонания укладывается в `OrderExecutionTimeoutMs` — если бюджета шагов не хватает, заявка снимается.
- **Нативный chase (`Chase:Mode = Native`) помечен как непроверенный**: имена параметров берутся из документации конкретной биржи и обязаны быть подтверждены на testnet до Live. Пока параметры не заданы, политика сама понижает режим до `Simulated`, а возможности бирж заданы таблицей `ExchangeCapabilityMap` — при обновлении CCXT её нужно сверять.
- `PostOnly`, `IOC`/`FOK` поддерживаются не всеми биржами: неподдерживаемое условие понижается до `GTC` с предупреждением (см. таблицу возможностей бирж).
- PnL и комиссии по-прежнему считаются по **taker**-ставке: даже если заявка исполнена как maker (post-only/chase), прибыль в отчёте занижена. Учёт `taker/maker` по фактическому исполнению — отдельная задача (нужно разбирать поле `takerOrMaker` из ответов CCXT).
- Сетевые задержки: между «сигналом» и исполнением второй ноги цена может уйти — несобранная связка откатывается автоматически (`reduceOnly`, с ретраями), а её остатки не бросаются, а регистрируются позицией и ребалансируются/закрываются циклом ведения.
- Частичные исполнения отслеживаются раздельно по ногам; перекос сверх `RebalanceTolerancePercent` устраняется обрезкой бóльшей ноги (limit `reduceOnly`).
- PnL считается по ценам исполнения биржи; комиссии — оценочно по taker-ставке (детальные комиссии биржи не парсятся).
- Одна арбитражная позиция на символ; маржа не резервируется заранее — робот ловит ошибку `InsufficientFunds` и пропускает сделку.
