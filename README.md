# FuturesArbBot

**Межбиржевой арбитражный робот для фьючерсов** на Python (uv) с использованием [ccxt / ccxt.pro](https://github.com/ccxt/ccxt) (WebSocket + REST) и консольного интерфейса [Rich](https://github.com/Textualize/rich). Порт функционально эквивалентен C#/.NET-версии: та же логика сканера, исполнения, уведомлений и отчётов.

Робот непрерывно опрашивает несколько криптобирж, сравнивает цены **линейных бессрочных фьючерсов (USDT-перпов)** по всем доступным торговым парам и находит расхождения, при которых одновременная покупка «там дешевле» и продажа «там дороже» приносит прибыль с учётом комиссий обеих бирж.

> ⚠️ **Дисклеймер.** Торговля фьючерсами с плечом — деятельность высокого риска. Данный проект — исследовательский инструмент, а не финансовый совет. Авторы не несут ответственности за финансовые потери. Всегда начинайте с режимов `DryRun` и `Testnet`.

## Возможности

- **Тикеры по WebSocket (ccxt.pro)**: котировки приходят из `watch_tickers` в фоновом потоке каждой биржи; REST `fetch_tickers` + `fetch_bids_asks` — буст на первом скане и запасной путь, если подписка биржи покрывает не все рынки.
- **Мониторинг всех доступных пар**: по умолчанию берутся все линейные бессрочные контракты в USDT с фильтром по обороту за 24 часа (для Binance досылаются bid/ask из bookTicker, объём OKX извлекается из сырых данных тикера).
- **Арбитраж по «коридору спреда»**: вход при расхождении **вверх** (`MinSpreadPercentUp`), фиксация прибыли при сжатии **вниз** (`MinSpreadPercentDown`, только если расчётный PnL немедленного выхода положителен), стоп-лосс (`StopLossSpreadPercent`), принудительное закрытие по возрасту (`MaxPositionAgeMinutes`).
- **Фильтр по фандинг-рейту**: считается **чистый** фандинг пары (рейт шорта − рейт лонга); строго ниже `MinFundingRatePercent` (по умолчанию −1 %) сделка не открывается. Рейты кэшируются на 5 минут; при недоступности данных фильтр не блокирует сделки (fail-open).
- **Учёт комиссий**: нетто = валовый спред − taker-комиссии **полного круга** (4 комиссии) − буфер `SlippageBufferPercent`. Комиссии подтягиваются из рынков ccxt, переопределяются в конфиге.
- **Режимы сети**: `DryRun` (симуляция) → `Testnet` (sandbox-URL биржи) → `Live` (требует `AllowLive = true`).
- **Настраиваемое исполнение заявок**: market / limit / chase-limit (догонание цены шагами: локальные перестановки или нативный chase биржи), смещение цены в bps, time-in-force (включая post-only), отдельная политика закрытия — с автоматическим безопасным понижением до того, что биржа действительно поддерживает (пояснения — в журнал, один раз).
- **Полный цикл открытия**: ноги выставляются последовательно, частичные исполнения и перекос ног (`RebalanceTolerancePercent`), откат неудавшегося открытия `reduceOnly`-ордерами с ретраями, «потерянные» заявки не забываются (цикл ведения доснимает), лимиты позиций считают **фактическую экспозицию бирж** (сверка `fetch_positions` раз в минуту) — после рестарта робот не открывает «ещё одну поверх забытой».
- **Живой дашборд** (Rich Live): шапка состояния, таблица лучших возможностей, журнал событий, строка статистики. Либо `--no-ui` — поток событий текстом.
- **Ctrl+C — корректная остановка** с итоговым отчётом: тики, тикеры, сигналы, сделки, PnL, топ символов, статистика по биржам, последние ошибки. Открытые позиции при `ClosePositionsOnExit = true` закрываются перед выходом.
- **Защита от аномалий**: санитарный потолок `MaxSpreadPercent` отсекает «фантомные» расхождения новых листингов и преп-маркетов; фильтры возраста (`MaxTickerAgeSeconds`) и перекоса котировок (`MaxTickerSkewSeconds`).
- **Push-уведомления администратору в MAX Messenger**: сигналы, прошедшие те же фильтры, что и торговля; очередь неблокирующая, с порогом, кулдауном на символ, лимитом в минуту и защитой от серии сбоев.
- **Модульная архитектура**: ядро не знает про ccxt — биржа за адаптером; конфигурация перечитывается «на лету»; тесты перенесены с xUnit-набора C#-версии (pytest).

## Быстрый старт

Нужен только [uv](https://docs.astral.sh/uv/) (Python ставить не надо — uv сам скачает нужный интерпретатор).

```powershell
uv sync                      # установка зависимостей (ccxt, rich, pyyaml, httpx, …)
copy .env.example .env       # ключи бирж и токен уведомлений — в .env (не в git)
uv run arb-bot --once        # одиночное сканирование + отчёт (без торговли)
uv run arb-bot               # живой дашборд
```

Проверьте `config/appsettings.yaml` перед запуском с реальной торговлей. Безопасная проверка без ордеров: `General.NetworkMode: DryRun` + `Arbitrage.Enabled: false`.

## Аргументы командной строки

| Аргумент | Описание |
|---|---|
| `--once` | выполнить одно сканирование, показать сводку и выйти |
| `--no-ui` | без Live-дашборда; события печатаются обычным потоком |
| `--config-dir <путь>` | каталог конфигурации (по умолчанию ищется `./config`) |
| `--notify-test` | проверить токен MAX и прислать тестовое сообщение в чат администратора |
| `--notify-chat-id` | показать chat_id: отправьте боту любое сообщение, робот прочитает его из `/updates` |
| `--help`, `-h` | справка |

Остановка — `Ctrl+C` (первый — корректная остановка с закрытием позиций и отчётом, повторный — принудительный выход).

## Конфигурация

Всё — в каталоге `config/` (YAML-ключи повторяют прежние PascalCase-имена JSON, конфигурация переносится без правок):

| Файл | Раздел | Назначение |
|---|---|---|
| `appsettings.yaml` | `General`, `Arbitrage` | режим сети, темп скана, пороги, политика исполнения `Execution` |
| `exchanges.yaml` | `Exchanges` | список бирж (Id = идентификаторы ccxt), права доступа, переопределения комиссий/исполнения |
| `symbols.yaml` | `Symbols` | котиры, минимальный оборот, include/exclude-шаблоны (`*`, `?`), возраст/перекос тикеров |
| `notifications.yaml` | `Notifications` | необязательный: push-уведомления в MAX Messenger |

Секреты — в `.env` (файл в `.gitignore`, образец — `.env.example`):

```
ARB_OKX_API_KEY=…   ARB_OKX_SECRET=…   ARB_OKX_PASSWORD=…   # ARB_<ID>_<КЛЮЧ>
ARB_Notifications__BotToken=…          # токен MAX-бота
```

Файлы перечитываются «на лету» (изменения вступают в силу без перезапуска, в пределах ~0,5 с). Переменные вида `ARB_<Раздел>__<Параметр>` перекрывают YAML (например `ARB_General__NetworkMode=dryrun`).

### Arbitrage.Execution — политика заявок

`Type: Market | Limit | ChaseLimit` (по умолчанию на входе — marketable Limit), `LimitOffsetBps` — смещение цены (BUY выше, SELL ниже; 1 bps = 0,01 %), `TimeInForce: Gtc | Ioc | Fok | PostOnly`, `Close` — отдельная политика закрытия (по умолчанию market; chase на закрытии не допускается). Догонание — подсекция `Chase`:

```yaml
Execution:
  Type: ChaseLimit
  LimitOffsetBps: 35
  TimeInForce: GTC
  Chase:
    Mode: Simulated        # Simulated — робот переставляет заявки; Native — chase-ордер биржи
    MaxSteps: 5            # перестановок до отказа
    StepIntervalMs: 400    # пауза между перестановками
    StepBps: 5             # шаг смещения цены к рынку
    MaxDeviationBps: 50    # бюджет отклонения от стартовой цены
    FallbackToMarket: true # добить остаток market-ордером
    # Params: { chaseType: priceChase }   # только для Mode: Native (KuCoin Futures)
  Close:
    Type: Limit
```

Раздел `Execution` можно задать и **у конкретной биржи** в `exchanges.yaml` — отличаются только перечисленные поля; остальное наследуется. Неподдерживаемые возможности понижаются безопасно (Post-only → GTC, Native → Simulated и т. п.) с однократным предупреждением в журнале; ошибки вида `Close:Close`, пустые `Params`, нативный chase без параметров блокируют запуск до подключения бирж.

## Уведомления (MAX Messenger)

1. Создайте бота в диалоге с `@MasterBot`, токен положите в `ARB_Notifications__BotToken` (или `Notifications.BotToken`).
2. Узнайте адресата: `uv run arb-bot --notify-chat-id`, затем отправьте боту любое сообщение — chat_id появится в выводе.
3. Запишите `AdminChatId`, включите `Notifications.Enabled: true` и проверьте канал: `uv run arb-bot --notify-test`.

Шаблон текста — `Notifications.TextTemplate` с подстановками `{symbol} {longExchange} {longPrice} {shortExchange} {shortPrice} {net} {gross} {longFee} {shortFee} {longFunding} {shortFunding} {volume} {time}`. Отправка неблокирующая: ограниченная очередь, кулдаун на символ (`SignalCooldownSeconds`), потолок `MaxPerMinute` в минуту, автопауза канала на `CircuitBreakMinutes` после `FailureCircuitLimit` неудач (при постоянной ошибке — сразу).

## Биржи

`exchanges.yaml` — список включённых бирж (Id — идентификаторы ccxt): `binanceusdm`, `binance`, `bybit`, `okx`, `gate`, `mexc`, `kucoinfutures`, `bitget`, `htx`, `coinex`, `phemex`, `krakenfutures`, `bingx`. Ключи — только для Testnet/Live (для мониторинга достаточно пустых); для Testnet робот включает sandbox-режим ccxt до загрузки рынков. Доступность `watch_tickers` определяется по `exchange.has` — на биржах без WS-тикеров скан автоматически остаётся на REST (как в C#-версии).

Возможности бирж по заявкам (post-only-токены, IOC/FOK, нативный chase) заданы таблицей `ExchangeCapabilityMap` — её нужно сверять при обновлении ccxt. Неизвестная биржа получает базовый набор (limit/cancel/fetch order).

## Отличия от C#-версии (порт 1:1 по поведению)

- **WebSocket-тикеры**: `ccxt.pro.watch_tickers` вместо REST `fetchTickers` на каждом тике; REST остаётся путём буста и резерва (в том числе когда подписка биржи покрывает < 90 % рынков).
- **Темп цикла**: в .NET паузу задавал сам REST-опрос с rate-limit; здесь `RefreshIntervalMs` выдерживается явно (между сканами досыпается остаток такта).
- **Журнал `EventLog.Latest`**: в C#-версии метод возвращал старейшие записи буфера вместо последних (расхождение с docstring «Последние события»); в порте — фактически последние, как задумано.
- **Числа — `Decimal`** (округление как в C#: `Math.Round` по умолчанию — midpoint-to-even, `AwayFromZero` для цен заявок), время — tz-aware UTC.

- Конфигурация — YAML + `.env` вместо JSON с `ARB_`-переменными; остальное — имена полей, пороги, тексты журнала/уведомлений — без изменений.

## FAQ

**Почему сигнал есть, а робот не торгует?** — По умолчанию `Arbitrage.Enabled = false`: это монитор. Включите торговлю и пройдите чек-лист режима сети (`AllowLive` для Live).

**Вижу спред 3 %, а робот молчит.** — Проверьте `MaxSpreadPercent` (аномалии отбрасываются), нетто-спред с учётом комиссий полного круга (может уйти в минус), объём и `MinQuoteVolume24hUsd`.

**Лимиты свободны, а новые арбитражи не открываются.** — Робот считает фактическую экспозицию бирж (сверка `fetch_positions` раз в минуту). Остатки после рестарта или ручные сделки под теми же ключами занимают слоты — ищите в журнале предупреждение «На биржах найдены позиции вне учёта этого сеанса».

**Реально ли заработать на межбиржевом арбитраже?** — Чистые расхождения на топ-биржах редки и малы (обычно < 0,2 %). Плюс: задержки сети, проскальзывание, лимиты бирж, перевод денег между биржами. Робот показывает реальную картину с учётом комиссий — решать вам.

**Много запросов к бирже?** — С WS-тикерами REST-запросы остаются только на заявки, позиции (раз в минуту) и фандинг (раз в 5 минут). На биржах без `watch_tickers` работает прежняя схема: тикеры каждые `RefreshIntervalMs` с `enableRateLimit`.

## Ограничения и риски

- Открытие исполняется limit-ордерами — риск не исполниться покрывается таймаутом с отменой и откатом; закрытие/откаты — рыночные ордера, на неликвидных парах возможно проскальзывание.
- Догонание цены (`ChaseLimit`) — компромисс скорости и цены: каждый шаг — отмена + новая заявка; весь цикл укладывается в `OrderExecutionTimeoutMs`.
- Нативный chase (`Chase:Mode = Native`) требует проверки на testnet; без `Params` политика понижает режим до `Simulated`.
- PnL и комиссии считаются по taker-ставке; учёт фактического `takerOrMaker` — отдельная задача.
- Одна арбитражная позиция на символ; маржа не резервируется — при `InsufficientFunds` сделка пропускается.
